# Q2.2 — Step 2: AI Prompt Rewrite

**Phase:** 2 — Input Processing  
**Depends on:** Q2.1  
**Required by:** Q3.1

## Goal

Pass the normalised query to GPT-4.1 mini and get back a structured `QueryAnalysis` — a cleaned query string plus routing metadata (intent, heuristic, filter) that drives every downstream step.

---

## Section A — `query/types.py` additions

Add `QueryAnalysis` alongside the existing `QueryRequest`:

```python
from dataclasses import dataclass, field


@dataclass
class QueryAnalysis:
    intent:    str         # "find_employees" | "others"
    query:     str         # keyword-dense rewrite for embedding
    heuristic: str         # plain-language instruction for Step 5
    filter:    dict = field(default_factory=dict)  # structured GIN filter; empty = no filter
```

**`intent` values:**

| Value | Meaning |
|---|---|
| `"find_employees"` | Return a ranked list of matching employees |
| `"others"` | Aggregation or lookup query (count, skill list, etc.) |

## Section B — `query/rewrite.py`

### System prompt

Store the prompt as a versioned module-level constant — never inline it in the function body.

```python
_REWRITE_PROMPT_V1 = """\
You are a search query rewriter for an employee skill-search system.

Given a natural-language query, return a JSON object with exactly these fields:

- "intent": one of "find_employees" or "others"
    - "find_employees" — the user wants a ranked list of employees (e.g. "who has Java skills?")
    - "others" — the user wants an aggregate or lookup (e.g. "how many", "list skills of")
- "query": a keyword-dense rewrite of the query for vector embedding
    - Fix typos and grammar ("developper" → "developer")
    - Expand common abbreviations ("FE" → "frontend", "BE" → "backend", "QA" → "quality assurance")
    - Remove filler ("Can you tell me who..." → "who...")
    - Keep all skills, tools, domains, roles, and seniority levels
- "heuristic": a plain-language instruction for the response step
    - For "find_employees": e.g. "rank employees by score descending"
    - For count queries: "count distinct matched employees above score threshold"
    - For skill lookups: "list skills of the matched employee"
- "filter": a JSON object of structured metadata filters to apply to the vector search
    - Use only keys that exist in the index metadata: "skills", "source_type", "date_from", "date_to"
    - Leave as {} if no structured filter applies

Examples:

Input:  "Who has Java backend experience and good English?"
Output: {"intent": "find_employees", "query": "java backend experience english communication", "heuristic": "rank employees by score descending", "filter": {}}

Input:  "How many employees know Python?"
Output: {"intent": "others", "query": "python skill", "heuristic": "count distinct matched employees above score threshold", "filter": {"skills": "Python"}}

Return only valid JSON. No markdown, no explanation.
"""
```

### Fallback constant

```python
_FALLBACK_HEURISTIC = "rank employees by score descending"


def _fallback(normalized: str) -> QueryAnalysis:
    return QueryAnalysis(
        intent="find_employees",
        query=normalized,
        heuristic=_FALLBACK_HEURISTIC,
        filter={},
    )
```

### `rewrite_query` function

```python
import json
import logging

from openai import OpenAI

from common.config import settings
from query.types import QueryAnalysis

_logger = logging.getLogger(__name__)
_client = OpenAI(api_key=settings.openai_api_key)


def analyze_query(normalized: str) -> QueryAnalysis:
    try:
        response = _client.chat.completions.create(
            model="gpt-4.1-mini",
            messages=[
                {"role": "system", "content": _REWRITE_PROMPT_V1},
                {"role": "user",   "content": normalized},
            ],
            response_format={"type": "json_object"},
            temperature=0,
        )
        data = json.loads(response.choices[0].message.content)
        return QueryAnalysis(
            intent=data["intent"],
            query=data["query"],
            heuristic=data["heuristic"],
            filter=data.get("filter", {}),
        )
    except Exception:
        _logger.warning(
            "analyze_query failed for query=%r — using fallback QueryAnalysis",
            normalized,
            exc_info=True,
        )
        return _fallback(normalized)
```

**Notes:**
- `temperature=0` for deterministic output
- `response_format={"type": "json_object"}` enforces JSON-only output from the model
- The `OpenAI` client is instantiated once at module level (not per-call)
- Any exception — network error, parse error, missing key — triggers the fallback; nothing propagates

## Q2.2.1 — Determine filter metadata (no AI)

Rather than asking the LLM to extract a filter, reuse `detect_skills` from `etl/impl/transform/metadata.py` to match skill names mentioned in the query against the canonical list from the DB. This produces the `filter` dict without any AI call.

> **Refactor note:** `detect_skills` and `get_all_skill_names` currently live in `etl/impl/transform/metadata.py`. Move them to `common/metadata.py` before use here, and update the ETL import. Same principle as the `normalize_text` move planned in Q2.1.

### Implementation

```python
from common.metadata import detect_skills, get_all_skill_names


def build_filter(normalized: str) -> dict:
    skill_names = get_all_skill_names()
    matched = detect_skills(normalized, skill_names)
    if matched:
        return {"skills": matched}
    return {}
```

**Behaviour:**
- Loads all skill names from the source DB (`skills` table) via `get_all_skill_names()`
- Runs case-insensitive substring match against the normalised query via `detect_skills()`
- Returns `{"skills": [<matched names>]}` when at least one skill is found, `{}` otherwise
- `get_all_skill_names()` should be cached per request (call once, pass the list down) to avoid repeated DB queries

### Deliverables
- [ ] `detect_skills` and `get_all_skill_names` moved to `common/metadata.py`; ETL import updated
- [ ] `build_filter(normalized: str) -> dict` in `query/rewrite.py`
- [ ] Returns `{}` when no skills match; returns `{"skills": [...]}` when one or more match

## Q2.2.2 — Determine intent (no AI)

Skip the LLM entirely for now. Always return `intent="find_employees"` with a fixed heuristic. The AI rewrite described in Section B above will be introduced later once the retrieval pipeline is validated end-to-end.

### Implementation

`rewrite_query` is simplified to a pure, synchronous function with no external calls:

```python
from query.types import QueryAnalysis


def analyze_query(normalized: str) -> QueryAnalysis:
    return QueryAnalysis(
        intent="find_employees",
        query=normalized,
        heuristic="rank employees by score descending",
        filter=build_filter(normalized),
    )
```

**Notes:**
- No OpenAI dependency at this stage — the function is deterministic and always succeeds
- The `query` field passes `normalized` through unchanged; the embedding step (Q3.1) receives clean, lowercased text from Q2.1
- The AI rewrite path in Section B is kept in this document as the target state; `_REWRITE_PROMPT_V1` will be wired in when AI is enabled

### Deliverables
- [ ] `analyze_query(normalized: str) -> QueryAnalysis` in `query/analyze_query.py` — no OpenAI call, always returns `intent="find_employees"`
- [ ] `filter` is populated via `build_filter()` (Q2.2.1)
- [ ] Function is pure and synchronous — no network calls, no exceptions

## Acceptance Tests

```python
from unittest.mock import MagicMock, patch
from query.rewrite import analyze_query
from query.types import QueryAnalysis


def _mock_response(content: str):
    msg = MagicMock()
    msg.content = content
    choice = MagicMock()
    choice.message = msg
    resp = MagicMock()
    resp.choices = [choice]
    return resp


@patch("query.rewrite._client")
def test_find_employees_intent(mock_client):
    mock_client.chat.completions.create.return_value = _mock_response(
        '{"intent": "find_employees", "query": "java backend experience", '
        '"heuristic": "rank employees by score descending", "filter": {}}'
    )
    result = analyze_query("who has java backend experience")
    assert result.intent == "find_employees"
    assert result.query == "java backend experience"
    assert result.heuristic == "rank employees by score descending"
    assert result.filter == {}


@patch("query.rewrite._client")
def test_others_intent(mock_client):
    mock_client.chat.completions.create.return_value = _mock_response(
        '{"intent": "others", "query": "python skill", '
        '"heuristic": "count distinct matched employees above score threshold", '
        '"filter": {"skills": "Python"}}'
    )
    result = analyze_query("how many employees know python")
    assert result.intent == "others"
    assert result.filter == {"skills": "Python"}


@patch("query.rewrite._client")
def test_fallback_on_api_failure(mock_client):
    mock_client.chat.completions.create.side_effect = Exception("timeout")
    result = analyze_query("find backend developers")
    assert result.intent == "find_employees"
    assert result.query == "find backend developers"
    assert result.filter == {}


@patch("query.rewrite._client")
def test_fallback_on_invalid_json(mock_client):
    mock_client.chat.completions.create.return_value = _mock_response("not json")
    result = analyze_query("find backend developers")
    assert result.intent == "find_employees"
```
