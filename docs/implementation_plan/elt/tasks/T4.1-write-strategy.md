# T4.1 — Step 1 (Load): Write Strategy

**Phase:** 4 — Load
**Depends on:** T3.5 (all `ChunkRecord.embedding` fields populated)
**Required by:** T4.2 (idempotency check), T5.1, T5.2, T5.3

## Goal

Atomically replace all indexed chunks for one employee in `skills_search_index`. The operation must be all-or-nothing: a mid-insert failure leaves the previous rows intact; a successful run leaves exactly `len(chunks)` rows for that `employee_id`.

The implementation spans two files:

- **`common/db.py`** — add `_vector_connect()` alongside the existing `_connect()` (source DB)
- **`etl/load.py`** — `load_employee()` function: DELETE + bulk INSERT in a single transaction

`etl/transform.py` remains unchanged by this task; `load_employee` is called by the pipeline coordinator (T3.6 / future trigger code).

## Section 1 — Vector DB Connection (`common/db.py`)

Add `_vector_connect()` as a `contextmanager` that mirrors `_connect()` but targets `settings.vector_db` and yields the **connection** (not a cursor) so the caller controls `COMMIT` / `ROLLBACK`.

### Contract

| Detail | Value |
|---|---|
| Config used | `settings.vector_db` (`VECTOR_DB_HOST/PORT/NAME/USER/PASSWORD`) |
| Yields | `psycopg2.connection` with `autocommit=False` (psycopg2 default) |
| On exception | `conn.rollback()` before closing |
| On clean exit | Caller must call `conn.commit()`; connection closed by `finally` |
| Cursor factory | `psycopg2.extras.RealDictCursor` (consistent with `_connect`) |

```python
@contextmanager
def _vector_connect():
    conn = psycopg2.connect(
        host=settings.vector_db.host,
        port=settings.vector_db.port,
        dbname=settings.vector_db.name,
        user=settings.vector_db.user,
        password=settings.vector_db.password,
    )
    try:
        yield conn
    except Exception:
        conn.rollback()
        raise
    finally:
        conn.close()
```

## Section 2 — `load_employee` (`etl/load.py`)

### Signature

```python
def load_employee(employee_id: int, chunks: list[ChunkRecord]) -> None:
```

### Row preparation

Each `ChunkRecord` maps to one DB row. Before insertion, the provenance fields that are not DB columns are merged into `metadata`:

```python
merged_metadata = {
    **chunk.metadata,
    "preprocess_version": chunk.preprocess_version,
    "char_start": chunk.char_start,
    "char_end": chunk.char_end,
    "token_count": chunk.token_count,
}
```

`chunk.embedding` (a `list[float]`) is serialised as a pgvector-compatible string:
`"[" + ",".join(str(x) for x in chunk.embedding) + "]"`.

The insert row tuple:
```
(employee_id, chunk_index, field_type, chunk_text, embedding_str, json.dumps(merged_metadata))
```

### INSERT SQL

```sql
INSERT INTO skills_search_index
    (employee_id, chunk_index, field_type, chunk_text, embedding, metadata)
VALUES %s
```

Use `psycopg2.extras.execute_values` with `page_size=500` for efficient bulk insertion.

### Algorithm

```
with _vector_connect() as conn:
    with conn.cursor() as cur:
        cur.execute(DELETE, (employee_id,))
        if chunks:
            execute_values(cur, INSERT_SQL, rows, page_size=500)
    conn.commit()
```

If an exception occurs anywhere inside the `with _vector_connect()` block, `_vector_connect` calls `conn.rollback()` before re-raising — the old rows are left intact.

### Contract

| Detail | Value |
|---|---|
| Input | `employee_id: int`, `chunks: list[ChunkRecord]` (all `embedding` fields are `list[float]`, not `None`) |
| Precondition | `ChunkRecord.embedding` must not be `None`; raises `ValueError` with a clear message if any chunk has `embedding=None` |
| Transaction | Single transaction: DELETE + INSERT committed atomically |
| Empty `chunks` | DELETE runs; no INSERT; employee's rows become 0 — this is valid (employee with no indexable content) |
| Performance | `execute_values` with `page_size=500`; handles ≥ 500 chunks without timeout |
| Return | `None` on success |
| On failure | Exception propagates; `_vector_connect` rolls back; `skills_search_index` unchanged |

### Guard against missing embeddings

```python
missing = [i for i, c in enumerate(chunks) if c.embedding is None]
if missing:
    raise ValueError(
        f"load_employee: chunks at indices {missing} have embedding=None; "
        "run embed_chunks() before load_employee()"
    )
```

## Unit Tests

File: `tests/test_load.py`

These tests use a live vector DB (marked `@pytest.mark.integration`). A fixture creates and tears down a dedicated schema or cleans the `skills_search_index` table for the test `employee_id` after each test.

### Atomicity

- **Happy path**: `load_employee(eid, chunks)` inserts exactly `len(chunks)` rows; all columns match the source `ChunkRecord`.
- **Rollback on error**: patch `execute_values` to raise after the DELETE; assert the old rows are still present (not deleted) and no new rows were inserted.

### Column mapping

- `embedding` round-trip: the stored `VECTOR(384)` value retrieved as text parses back to a list matching the original `chunk.embedding` within floating-point precision.
- `metadata` JSON: `merged_metadata` keys (`preprocess_version`, `char_start`, `char_end`, `token_count`, plus any entity metadata) are all present in the stored JSONB.

### Guard

- Passing a chunk with `embedding=None` raises `ValueError` before any DB connection is opened.
