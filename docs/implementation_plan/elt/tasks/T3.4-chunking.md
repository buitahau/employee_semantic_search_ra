# T3.4 — Step 4: Chunking

**Phase:** 3 — Transform
**Depends on:** T3.3
**Required by:** T3.5

---

## Goal

For each entity in `EmployeeData`, split its combined text fields into overlapping sentence-window chunks (≤ 250 tokens for cv/experience, ≤ 200 for others), and produce typed `ChunkRecord` instances stored directly on each entity. Intermediate results (token counts, sentence spans, windows) are held in `pipeline_state`; the final pass converts windows into `ChunkRecord` objects on `entity.chunks`.

The task is split into four sections, each in its own file inside `etl/impl/transform/chunking/`:

- **Section 1** — `tokenizer.py` — load once; count tokens per text fragment
- **Section 2** — `splitter.py` — break text into spans with character positions
- **Section 3** — `accumulator.py` — build windows ≤ `tokens_max` with ≥ 40-token overlap
- **Section 4** — `chunking/__init__.py` — four-pass orchestrator over `EmployeeData`

`etl/transform.py` (the transform coordinator) calls `chunking()` from `etl.impl.transform.chunking`.

```
EmployeeData (T3.3)
       ↓ _fill_token_counts()
entity.pipeline_state["token_count"] = int
       ↓ _fill_sentences()

       ↓ _fill_windows()

```

## ChunkRecord Dataclass

Defined in `common/types.py`. Each instance represents one chunk window from one source entity.

| Field | Type | Description |
|---|---|---|
| `employee_id` | `int` | Links the chunk to its employee |
| `field_type` | `str` | Source type: `"cv"`, `"experience"`, `"employment_history"`, `"training"`, `"task"`, `"user_skill"` |
| `chunk_text` | `str` | The raw window text (sentences joined by space, no prefix) |
| `chunk_index` | `int` | 0-based position within this entity's window list |
| `char_start` | `int` | Start offset in the entity's combined text |
| `char_end` | `int` | End offset (exclusive) in the entity's combined text |
| `token_count` | `int` | Token count of `chunk_text` |
| `preprocess_version` | `str` | `str(PREPROCESS_VERSION)` from `common/constants.py` |
| `embedding` | `list[float] \| None` | `None` until T3.5 fills it in |
| `metadata` | `dict` | Copied from the source entity's `metadata` field (populated by T3.3) |

`ChunkRecord` is defined before the entity classes in `common/types.py` so that `Cv`, `Experience`, and the rest can reference it directly in their `chunks: list[ChunkRecord]` field.

## Section 1 — Tokenizer

**File:** `etl/impl/transform/chunking/tokenizer.py`

Load the `all-MiniLM-L6-v2` tokenizer once, lazily, from the same directory as `EMBEDDING_MODEL_PATH`.

### Contract

| Detail | Value |
|---|---|
| File loaded | `{parent(EMBEDDING_MODEL_PATH)}/tokenizer.json` |
| Library | `tokenizers` (HuggingFace fast tokenizer) |
| Initialisation | Lazy singleton — loaded once, reused on all subsequent calls |
| `_count_tokens` | Returns number of token IDs for the given string |

`_count_tokens` is called once per entity (pass 1) and once per emitted window (pass 3) to populate the 4th element of each window tuple.

---

## Section 2 — Sentence Splitter

**File:** `etl/impl/transform/chunking/splitter.py`

Split text into sentence spans. A boundary is `.`, `!`, or `?` followed by one or more whitespace characters.

### Contract

| Detail | Value |
|---|---|
| Boundary | `.`, `!`, or `?` followed by `\s+` (lookbehind) |
| Empty / whitespace-only input | Returns `[]` |
| No boundaries | Returns one tuple covering the entire stripped text |
| `char_start` / `char_end` | Offsets into the original `text`; `char_end` is exclusive |
| Sentence string | Leading/trailing whitespace stripped |
| Adjacent sentences | Share their boundary: sentence N's `char_end` equals sentence N+1's `char_start` |

## Section 3 — Greedy Window Accumulator

**File:** `etl/impl/transform/chunking/accumulator.py`

Accumulate sentences into windows respecting per-source-type token limits, with ≥ `OVERLAP_MIN` token overlap between consecutive windows.

### Constants

| Name | Value | Role |
|---|---|---|
| `TOKENS_MAX` | 250 | Default per-window token budget (cv, experience) |
| `OVERLAP_MIN` | 40 | Minimum target overlap between consecutive windows |

### `_accumulate_windows`

Takes a sentence list, a prefix string, and a per-source `tokens_max`. Returns a list of `(window_text, char_start, char_end, token_count)` tuples.

**Algorithm:**

1. Walk sentences left to right, accumulating into `current`.
2. Before adding sentence `s`, check if `prefix + join(current + [s])` exceeds `tokens_max`.
3. If it does and `current` is non-empty: emit a window from `current`, then build an overlap region by walking `current` backwards until the cumulative token count reaches `OVERLAP_MIN`. Start the new `current` from that overlap.
4. If sentence `s` alone exceeds `tokens_max`: flush `current`, then delegate to `_token_window_split` for fixed token-width sub-windows.
5. After all sentences: emit remaining `current`.

**Overlap semantics:** Walk `current` backwards, adding sentences until cumulative tokens ≥ `OVERLAP_MIN`. Always includes at least one sentence. No hard upper cap — short terminal sentences pull in additional context to ensure meaningful continuity.

### `_token_window_split`

Fallback for single sentences that exceed `tokens_max`. Uses the tokenizer's character-offset map (`Encoding.offsets`) to produce fixed-width token windows with `OVERLAP_MIN`-token stride overlap. Character positions are exact.

### Contract

| Detail | Value |
|---|---|
| Return type | `list[tuple[str, int, int, int]]` — `(window_text, char_start, char_end, token_count)` |
| Single sentence ≤ `tokens_max` | Produces one window; no overlap |
| Overlap guarantee | `char_start` of window N+1 ≤ `char_end` of window N |
| Long-sentence fallback | `_token_window_split` uses tokenizer `Encoding.offsets` for exact character positions |
| `count_fn` | `None` defaults to `_count_tokens` via runtime lookup (allows mock.patch in tests) |

## Section 4 — `chunking` Orchestrator

**File:** `etl/impl/transform/chunking/__init__.py`

Four-pass orchestrator over the full `EmployeeData` object.

### Lookup tables

**`_TOKENS_MAX_BY_SOURCE`** — per-source token budget:
- `cv`, `experience` → 250 (`TOKENS_MAX`)
- `employment_history`, `training`, `task`, `user_skill` → 200

**`_PREFIX_BY_SOURCE`** — prefix string passed to `_accumulate_windows` for budget accounting:
- `cv` → `"CV: "`, `experience` → `"Experience: "`, `employment_history` → `"Employment: "`, `training` → `"Training: "`, `task` → `"Task: "`, `user_skill` → `"Skill: "`

Note: the prefix is used for token counting only. It is **not** prepended to `chunk_text` stored in `ChunkRecord` — the raw window text is stored as-is.

### Passes

| Pass | Function | Output |
|---|---|---|
| 1 | `_fill_token_counts` | `entity.pipeline_state["token_count"]` — raw token count of the entity's combined text |
| 2 | `_fill_sentences` | `entity.pipeline_state["sentences"]` — `list[(text, char_start, char_end)]` |
| 3 | `_fill_windows` | `entity.pipeline_state["windows"]` — `list[(text, char_start, char_end, token_count)]` |
| 4 | `_fill_chunks` | `entity.chunks` — `list[ChunkRecord]` |

**Pass 4 detail:** `_make_chunks` converts the windows list for one entity into `ChunkRecord` instances. `chunk_index` is the 0-based position within that entity's window list. `preprocess_version` is `str(PREPROCESS_VERSION)`. `embedding` is left `None`. `metadata` is copied from the entity's `metadata` dict as-is.

### Contract

| Detail | Value |
|---|---|
| Input / output | `EmployeeData` → `EmployeeData` (mutates in place) |
| Entity with no text | `pipeline_state` left without `"sentences"` / `"windows"` keys; `entity.chunks` remains `[]` |
| `ChunkRecord.embedding` | Always `None` on exit — filled by T3.5 |
| `ChunkRecord.preprocess_version` | `str(PREPROCESS_VERSION)` |

## Unit Tests

File: `tests/test_chunking.py`

### Sentence splitter

- Basic splitting on `.` — correct sentence strings and count
- Character positions: `text[char_start:char_end].strip() == sentence` for every span
- No boundary → single tuple covering the full text
- Empty string → `[]`
- Whitespace-only → `[]`
- `!` and `?` boundaries are recognised
- Sentence order is preserved

### Greedy accumulator (explicit `count_fn` — no model files required)

- Single sentence produces one window
- Multiple short sentences that fit → one window
- Sentences that overflow → at least two windows
- Custom `tokens_max` produces more windows than the default
- Overlap property: consecutive window `char_start` / `char_end` ranges overlap
- Short last sentence pulls in predecessor to reach `OVERLAP_MIN`
- Empty sentence list → `[]`

### `chunking` orchestrator (patch tokenizer — no model files required)

- CV token count populated correctly
- CV with all-`None` text fields → `token_count == 0`
- No CV → `_count_tokens` never called
- Experience token count correct across multiple fields
- CV `pipeline_state["sentences"]` populated
- CV `pipeline_state["windows"]` populated as 4-tuples
- CV uses `tokens_max = 250`; other types use `tokens_max = 200`
- Multiple experiences each get their own token count
