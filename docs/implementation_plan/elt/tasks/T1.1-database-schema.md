## Goal

---

## Section A — pgvector Database: `skills_search_index`

**Target DB:** Vector DB (`VECTOR_DB_*` connection)

### `migrations/001_create_skills_search_index.sql`

Creates the `skills_search_index` table. Must be idempotent (`IF NOT EXISTS` on table and indexes).

```sql
-- Verify pgvector is available
SELECT '[1,2,3]'::vector(3);

CREATE TABLE IF NOT EXISTS skills_search_index (
    id               BIGSERIAL PRIMARY KEY,
    employee_id      INTEGER       NOT NULL,
    chunk_index      INTEGER       NOT NULL,
    field_type       TEXT          NOT NULL,  -- 'cv', 'training_log', 'task'
    chunk_text       TEXT          NOT NULL,
    normalized_text  TEXT,
    ai_search_text   TEXT,
    embedding        VECTOR(384)   NOT NULL,
    metadata         JSONB         NOT NULL DEFAULT '{}',
    indexed_at       TIMESTAMPTZ   NOT NULL DEFAULT NOW(),

    CONSTRAINT uq_skills_search_index_employee_chunk
        UNIQUE (employee_id, chunk_index)
);

-- GIN index for fast JSONB filtering (skills, source_type, date ranges, etc.)
CREATE INDEX IF NOT EXISTS idx_skills_search_index_metadata
    ON skills_search_index USING GIN (metadata);

-- HNSW index for ANN vector search (pgvector >= 0.5.0)
CREATE INDEX IF NOT EXISTS idx_skills_search_index_embedding
    ON skills_search_index USING hnsw (embedding vector_cosine_ops);
```

> **Verification step** — the `SELECT '[1,2,3]'::vector(3);` line at the top will error immediately if the pgvector extension is not installed, making the failure obvious before any DDL runs.

### Schema: `skills_search_index`

| Column | Type | Nullable | Notes |
|---|---|---|---|
| `id` | `BIGSERIAL` | NO | PK |
| `employee_id` | `INTEGER` | NO | FK-style ref to employees |
| `chunk_index` | `INTEGER` | NO | Zero-based position within employee's chunks |
| `field_type` | `TEXT` | NO | Source type: `'cv'`, `'training_log'`, `'task'` |
| `chunk_text` | `TEXT` | NO | Raw chunk sent to embedding model (includes source-type prefix) |
| `normalized_text` | `TEXT` | YES | Output of T3.1 normalization step |
| `ai_search_text` | `TEXT` | YES | Output of T3.2 AI cleanup step |
| `embedding` | `VECTOR(384)` | NO | L2-normalised 384-dim vector from `all-MiniLM-L6-v2` |
| `metadata` | `JSONB` | NO | Structured metadata from T3.3 (skills, dates, source type, etc.) |
| `indexed_at` | `TIMESTAMPTZ` | NO | Timestamp of last successful index run for this chunk |

**Constraints:**
- `UNIQUE (employee_id, chunk_index)` — used by `ON CONFLICT` in the load step (T4.1) to replace stale chunks atomically
- `GIN` index on `metadata` — enables fast filtering by `metadata->>'source_type'`, `metadata->'skills'`, etc.
- `HNSW` index on `embedding` — enables approximate nearest-neighbour search with cosine distance

## Section B — Traditional PostgreSQL Database: `last_index_at`

**Target DB:** Source DB (`SOURCE_DB_*` connection — `owt-employee-app-backend`)

### `migrations/002_add_last_index_at.sql`

Adds `last_index_at TIMESTAMPTZ` to each source entity table. Must be idempotent.

```sql
ALTER TABLE user_cvs
    ADD COLUMN IF NOT EXISTS last_index_at TIMESTAMPTZ DEFAULT NULL;

ALTER TABLE cv_overview
    ADD COLUMN IF NOT EXISTS last_index_at TIMESTAMPTZ DEFAULT NULL;

ALTER TABLE user_skills
    ADD COLUMN IF NOT EXISTS last_index_at TIMESTAMPTZ DEFAULT NULL;

ALTER TABLE experiences
    ADD COLUMN IF NOT EXISTS last_index_at TIMESTAMPTZ DEFAULT NULL;

ALTER TABLE experience_skills
    ADD COLUMN IF NOT EXISTS last_index_at TIMESTAMPTZ DEFAULT NULL;

ALTER TABLE employment_histories
    ADD COLUMN IF NOT EXISTS last_index_at TIMESTAMPTZ DEFAULT NULL;

ALTER TABLE trainings
    ADD COLUMN IF NOT EXISTS last_index_at TIMESTAMPTZ DEFAULT NULL;

ALTER TABLE task_assignments
    ADD COLUMN IF NOT EXISTS last_index_at TIMESTAMPTZ DEFAULT NULL;

ALTER TABLE task_assignments_assignees
    ADD COLUMN IF NOT EXISTS last_index_at TIMESTAMPTZ DEFAULT NULL;
```

> **Semantics** — `last_index_at` is set to `NOW()` whenever a row is successfully included in an indexing run. A `NULL` value means the row has never been indexed. The reconciliation job (T5.2) treats a row as stale when `updated_at > last_index_at OR last_index_at IS NULL`.

### Schema: `last_index_at` column (source entity tables)

| Table | Column added |
|---|---|
| `user_cvs` | `last_index_at TIMESTAMPTZ DEFAULT NULL` |
| `cv_overview` | `last_index_at TIMESTAMPTZ DEFAULT NULL` |
| `user_skills` | `last_index_at TIMESTAMPTZ DEFAULT NULL` |
| `experiences` | `last_index_at TIMESTAMPTZ DEFAULT NULL` |
| `experience_skills` | `last_index_at TIMESTAMPTZ DEFAULT NULL` |
| `employment_histories` | `last_index_at TIMESTAMPTZ DEFAULT NULL` |
| `trainings` | `last_index_at TIMESTAMPTZ DEFAULT NULL` |
| `task_assignments` | `last_index_at TIMESTAMPTZ DEFAULT NULL` |
| `task_assignments_assignees` | `last_index_at TIMESTAMPTZ DEFAULT NULL` |

## Stale-Row Detection Query (preview for T5.2)

The reconciliation job will use a query like:

```sql
SELECT DISTINCT employee_id
FROM (
    SELECT employee_id FROM user_cvs
        WHERE last_index_at IS NULL OR updated_at > last_index_at
    UNION
    SELECT employee_id FROM user_skills
        WHERE last_index_at IS NULL OR updated_at > last_index_at
    UNION
    SELECT employee_id FROM experiences
        WHERE last_index_at IS NULL OR updated_at > last_index_at
    UNION
    SELECT employee_id FROM employment_histories
        WHERE last_index_at IS NULL OR updated_at > last_index_at
    UNION
    SELECT employee_id FROM trainings
        WHERE last_index_at IS NULL OR updated_at > last_index_at
    UNION
    SELECT ta.employee_id
    FROM task_assignments ta
    JOIN task_assignments_assignees taa ON taa.task_assignment_id = ta.id
        WHERE taa.last_index_at IS NULL OR taa.updated_at > taa.last_index_at
) stale;
```

## Acceptance Test

### Section A — Run against the pgvector DB

```sql
-- 1. pgvector is active
SELECT '[1,2,3]'::vector(3);

-- 2. Table exists with correct structure
SELECT column_name, data_type
FROM information_schema.columns
WHERE table_name = 'skills_search_index'
ORDER BY ordinal_position;

-- 3. UNIQUE constraint is enforced
INSERT INTO skills_search_index (employee_id, chunk_index, chunk_text, embedding, metadata)
VALUES (1, 0, 'test', '[0,0,...,0]'::vector(384), '{}');
-- Second insert with same (employee_id, chunk_index) must raise a unique violation:
INSERT INTO skills_search_index (employee_id, chunk_index, chunk_text, embedding, metadata)
VALUES (1, 0, 'duplicate', '[0,0,...,0]'::vector(384), '{}');

-- 4. GIN index exists
SELECT indexname FROM pg_indexes
WHERE tablename = 'skills_search_index' AND indexdef ILIKE '%gin%';

-- 5. HNSW index exists
SELECT indexname FROM pg_indexes
WHERE tablename = 'skills_search_index' AND indexdef ILIKE '%hnsw%';
```
