# T3.3 — Step 3: Metadata Extraction

**Phase:** 3 — Transform  
**Depends on:** T3.2  
**Required by:** T3.4

---

## Goal

After normalization (T3.1) and AI cleanup (T3.2), extract a structured `metadata` dictionary that travels with every chunk through T3.4 (chunking) and T3.5 (embedding), and is stored in the `metadata JSONB` column of `skills_search_index`.

The task is split into three sections:
- **Section 1** — Load all skill names from the `skills` table (source DB)
- **Section 2** — Detect which skills appear in a given text
- **Section 3** — Assemble the final metadata dict

---

## Data Flow

```
skills table (source DB)
       ↓ Section 1
skill_names: list[str]
       ↓ Section 2
ai_search_text (T3.2)  ──►  detect_skills()  ──►  skills: list[str]
       ↓ Section 3
extract_metadata(employee_id, skills, ...)  ──►  metadata dict
```

---

## Final Metadata Shape

```json
{
    "employee_id": 42,
    "skills": ["Vue.js", "Node.js", "PostgreSQL", "Redis"]
}
```

| Field | Type | Required | Description |
|---|---|---|---|
| `employee_id` | `int` | **mandatory** | Employee this chunk belongs to |
| `skills` | `list[str]` | **mandatory** | Skills detected in `ai_search_text` |
| `domain` | `str \| None` | optional | Experience domain — added in a later task |
| *(other fields)* | — | optional | Position, years, title, etc. — added in later tasks |

> Optional fields are extension points for later tasks. T3.3 only populates `employee_id` and `skills`.

---

## Section 1 — Load Skill Names

Query all known skill names from the `skills` table in the source DB. This list is loaded once per pipeline run and passed into Section 2.

**Location:** `query/__init__.py` (alongside T2.1 query functions)

```python
def get_all_skill_names(conn) -> list[str]:
    with conn.cursor() as cur:
        cur.execute("SELECT name FROM skills ORDER BY name")
        return [row[0] for row in cur.fetchall()]
```

### Contract

| Detail | Value |
|---|---|
| Table | `skills` |
| Column | `name` |
| Ordering | Alphabetical (`ORDER BY name`) |
| Returns | `list[str]` — empty list if the table has no rows |
| Connection | psycopg2 connection to `SOURCE_DB_*` |

> The result is passed as `skill_names: list[str]` into `detect_skills`. Load it once per indexing run, not once per employee.

---

## Section 2 — Detect Skills

Check which skill names from the global list appear in the given text. The check is a **case-insensitive substring match** — no NLP, no tokenization.

**Location:** `etl/transform.py`

```python
def detect_skills(text: str | None, skill_names: list[str]) -> list[str]:
    if not text:
        return []
    text_lower = text.lower()
    return [name for name in skill_names if name.lower() in text_lower]
```

### Contract

| Detail | Value |
|---|---|
| Match strategy | Case-insensitive substring (`name.lower() in text.lower()`) |
| Input `text` | `ai_search_text` from T3.2; `None` or empty → returns `[]` |
| Input `skill_names` | Full list from Section 1 |
| Output order | Preserves insertion order of `skill_names` (alphabetical from DB) |
| Duplicates | None — each skill name appears at most once |

### Examples

| `text` | `skill_names` | Output |
|---|---|---|
| `"Uses PostgreSQL and Redis for storage."` | `["FastAPI", "PostgreSQL", "Python", "Redis"]` | `["PostgreSQL", "Redis"]` |
| `"Expert in vue.js daily"` | `["Vue.js"]` | `["Vue.js"]` |
| `None` | `["Python"]` | `[]` |
| `""` | `["Python"]` | `[]` |

---

## Section 3 — Assemble Metadata

Combine `employee_id` and the detected `skills` into the final metadata dict. Optional fields are passed in as keyword arguments — unknown keys are ignored for now but the signature is designed to accept them without breaking.

**Location:** `etl/transform.py`

```python
def extract_metadata(
    employee_id: int,
    skills: list[str],
    **optional_fields,
) -> dict:
    return {
        "employee_id": employee_id,
        "skills": skills,
        **{k: v for k, v in optional_fields.items() if v is not None},
    }
```

### Contract

| Detail | Value |
|---|---|
| `employee_id` | Written into the dict unchanged |
| `skills` | The list returned by `detect_skills` |
| `**optional_fields` | Passed through only if value is not `None` — absent keys do not appear in the dict |

### Usage (called from T3.6 transform coordinator)

```python
skill_names = get_all_skill_names(source_conn)   # once per run

# per source record:
skills = detect_skills(ai_search_text, skill_names)
metadata = extract_metadata(employee_id=42, skills=skills)
# → {"employee_id": 42, "skills": ["Vue.js", "PostgreSQL"]}
```

## Section 4 — Enrich EmployeeData with Metadata

Walk every source record in a `EmployeeData`, run Sections 2–3 on each one, and return an updated `EmployeeData` where every row carries a populated `metadata` field.

### Dataclass Changes

All six entity classes in `common/types.py` already carry `metadata: dict = field(default_factory=dict)` (added as part of T2.1 class definitions). No new classes needed. Example:

```python
@dataclass
class Cv:
    cv: str | None
    custom_position: str | None
    introduction: str | None
    updated_at: datetime
    metadata: dict = field(default_factory=dict)
```

The `metadata` field defaults to `{}` so T3.1 and T3.2 pass through existing instances unchanged — T3.3 is the first stage that populates it.

### Text Fields Used Per Source Type

Each row uses the concatenation of its meaningful text fields as input to `detect_skills`:

| Source type | Text fields concatenated |
|---|---|
| `cv` | `cv.cv` + `cv.introduction` |
| `experience` | `description` + `roles_and_responsibilities` |
| `employment_history` | `company` |
| `training` | `training_title` + `training_description` |
| `task` | `title` + `details` |
| `user_skill` | `skill_name` |

Fields are joined with a single space; `None` fields are skipped.

### Function: `enrich_with_metadata`

**Location:** `etl/transform.py`

```python
import dataclasses

def _join_texts(*texts: str | None) -> str:
    return " ".join(t for t in texts if t)


def enrich_with_metadata(
    data: EmployeeData,
    skill_names: list[str],
) -> EmployeeData:
    eid = data.employee_id

    cv = None
    if data.cv:
        text = _join_texts(data.cv.cv, data.cv.introduction)
        cv = dataclasses.replace(
            data.cv,
            metadata=extract_metadata(eid, detect_skills(text, skill_names)),
        )

    experiences = [
        dataclasses.replace(
            row,
            metadata=extract_metadata(
                eid,
                detect_skills(_join_texts(row.description, row.roles_and_responsibilities), skill_names),
            ),
        )
        for row in data.experiences
    ]

    employment_histories = [
        dataclasses.replace(
            row,
            metadata=extract_metadata(eid, detect_skills(row.company, skill_names)),
        )
        for row in data.employment_histories
    ]

    trainings = [
        dataclasses.replace(
            row,
            metadata=extract_metadata(
                eid,
                detect_skills(_join_texts(row.training_title, row.training_description), skill_names),
            ),
        )
        for row in data.trainings
    ]

    tasks = [
        dataclasses.replace(
            row,
            metadata=extract_metadata(
                eid,
                detect_skills(_join_texts(row.title, row.details), skill_names),
            ),
        )
        for row in data.tasks
    ]

    skills = [
        dataclasses.replace(
            row,
            metadata=extract_metadata(eid, detect_skills(row.skill_name, skill_names)),
        )
        for row in data.skills
    ]

    return dataclasses.replace(
        data,
        cv=cv,
        experiences=experiences,
        employment_histories=employment_histories,
        trainings=trainings,
        tasks=tasks,
        skills=skills,
    )
```

### Usage (called from T3.6 transform coordinator)

```python
skill_names = get_all_skill_names(source_conn)   # once per run

normalized = normalize(raw)                      # T3.1
# ... T3.2 AI cleanup ...
enriched = enrich_with_metadata(normalized, skill_names)  # T3.3

# Each row now carries metadata:
# enriched.cv.metadata        → {"employee_id": 42, "skills": [...]}
# enriched.experiences[0].metadata → {"employee_id": 42, "skills": [...]}
```

import pytest
from etl.transform import detect_skills, extract_metadata


# --- detect_skills ---

def test_detect_skills_basic():
    assert detect_skills(
        "Uses PostgreSQL and Redis for storage.",
        ["FastAPI", "PostgreSQL", "Python", "Redis"],
    ) == ["PostgreSQL", "Redis"]

def test_detect_skills_case_insensitive():
    assert detect_skills("expert in vue.js daily", ["Vue.js"]) == ["Vue.js"]

def test_detect_skills_none_text():
    assert detect_skills(None, ["Python"]) == []

def test_detect_skills_empty_text():
    assert detect_skills("", ["Python"]) == []

def test_detect_skills_empty_skill_names():
    assert detect_skills("Expert in Python", []) == []

def test_detect_skills_no_match():
    assert detect_skills("Expert in Python", ["Go", "Rust"]) == []

def test_detect_skills_preserves_original_casing():
    # Output uses casing from skill_names, not from text
    result = detect_skills("uses node.js and POSTGRESQL", ["Node.js", "PostgreSQL"])
    assert result == ["Node.js", "PostgreSQL"]

def test_detect_skills_no_duplicates():
    # "python" appears twice in text — skill appears only once in output
    result = detect_skills("python and more python", ["Python"])
    assert result == ["Python"]


# --- extract_metadata ---

def test_extract_metadata_mandatory_fields():
    meta = extract_metadata(employee_id=42, skills=["Vue.js", "Node.js"])
    assert meta == {"employee_id": 42, "skills": ["Vue.js", "Node.js"]}

def test_extract_metadata_empty_skills():
    meta = extract_metadata(employee_id=1, skills=[])
    assert meta == {"employee_id": 1, "skills": []}

def test_extract_metadata_optional_field_included():
    meta = extract_metadata(employee_id=42, skills=["Python"], domain="Insurance")

def test_extract_metadata_optional_none_excluded():

## Deliverables Checklist

- [ ] `get_all_skill_names(conn) -> list[str]` in `query/` — queries `SELECT name FROM skills ORDER BY name`; returns `[]` for empty table
- [ ] `detect_skills(text, skill_names) -> list[str]` in `etl/transform.py` — case-insensitive substring match; returns `[]` for `None` or empty text; no duplicates in output
- [ ] `extract_metadata(employee_id, skills, **optional_fields) -> dict` in `etl/transform.py` — always includes `employee_id` and `skills`; omits optional fields with `None` value
- [ ] `metadata: dict = field(default_factory=dict)` added to all six `NormalizedXxxRow` dataclasses in `common/types.py`
- [ ] `_join_texts(*texts) -> str` helper — joins non-`None` values with a single space
- [ ] `enrich_with_metadata(data, skill_names) -> EmployeeData` in `etl/transform.py` — populates `metadata` on every row using the text fields listed in the table above; `cv=None` passes through as `None`; empty lists produce no metadata calls
- [ ] Unit tests cover: basic match, case-insensitivity, `None`/empty input, no-match, casing preservation, no-duplicates, mandatory fields, `None` optional field excluded, all six row types enriched, `cv=None` case, empty employee
